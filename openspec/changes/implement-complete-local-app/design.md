# Design

## Boundaries
Typed control-plane DTOs and repository interfaces isolate persistence. SQLite stores metadata, events, stage attempts, settings, retrospectives and idempotency. Injectable SQLite LangGraph checkpoints preserve suspended execution. Existing builders gain optional checkpointer injection with MemorySaver default for compatibility. WorkflowService owns graph construction/start/decision/recovery, exposing only its DTOs to the API. A bounded single-process worker serializes run execution and persists events. Startup reconciles interrupted workers from checkpoints; no uncertain external action is replayed automatically.

## Execution
All five business workflows use ModelStageExecutor with a live ModelGateway or explicitly selected simulation executor. Live model adapters support LM Studio, OpenAI Responses and Anthropic Messages behind the gateway. Explicit routing defaults to local-only; credentials stay in environment variables. Simulation derives contract-valid demonstration artifacts, never claims evidence or external execution, and is clearly flagged everywhere. Product Launch resolves the approved specification from a completed Watch Development run with production approval in the same mode. No browser-provided approved boolean is trusted. Live publishing adapters are not configured; commands expose this limitation and fail at the external action boundary rather than recording success.

## Safety, durability and feedback
Commands use persistent idempotency keys and approval revision compare-and-set. HTTP rejects unknown/stale decisions before scheduling resume; repeated identical decision identities return recorded state. Held runs require an explicit resume that reopens the original gate, never implicit approval. Persisted SSE event IDs support replay. Knowledge reads use an enforced root and bounded content; simulation never writes the external vault. Writes are explicit founder commands through ToolGateway/Policy with registered skill identity and audit. Origin/host checks protect local mutation endpoints; no public binding.

Retrospectives select completed runs with finite context (12,000 chars), at most four participants and one contribution each plus Elena synthesis. New typed retrospective skills preserve skill permission checks. Model failures remain visible/retryable. Review approves proposed experiments only; no automatic code, rights, prices or publishing changes. Experiment records require baseline, metric, target, owner, risk and evidence; results retain inconclusive outcomes. Exporting an approved learning is an explicit knowledge-write action. No automatic recurring loop.

## UI
German application with dark ink navigation, warm ivory workspace, brass accents and original SVG pixel office. Shared process launch forms, reliable loading/errors/empty states, responsive layout, keyboard list alternative, reduced-motion, zoom/pan, current work/history, replayable event refresh, real approval controls and source-backed KPI drill-down. Typed client uses REST only; SSE signals refresh. No credentials, private prompts or arbitrary filesystem controls in browser.

## Verification
Backend tests cover all five workflows, restart/resume at approvals, stale/repeated commands, forged prerequisites, unknown model results, local-only routing, knowledge traversal, metric time boundaries, retrospective review and experiment constraints. Frontend component tests and Playwright exercise navigation, forms, run/approval actions and screenshots. Full Python suite, TypeScript checks, production build and OpenSpec validator run before completion.
